- the bundled disk images still carry the pre-98eb6a1 w8.com and r8.com, so
nothing this port gained from the v1.36 core is visible to a user yet.  W8
neither probes HBF_HOST_CAPS (0xE9) nor asks HBF_HOST_GETNAME (0xE8), so the
capability bit this port now asserts and the Exports path it now reports both
go unread; W8 still truncates a binary export at the first 1Ah byte; and the
old R8's ambiguous-FCB bug, which erases every matching CP/M file before
creating the new one, is still live.  READ
romwbw_emu/docs/RELEASE_ORDER_2026-08-25.md BEFORE PUBLISHING ANYTHING: the
refresh is what arms a data-destruction bug in ioscpm, so the port fixes go
first, refreshed images must never be attached to the existing v1.4.5 tag
(DiskCatalogRepository.kt:27 pins it, and every installed app would start
fetching them with no update), and no image whose w8.com lacks the 0xE9 probe
may be published to any tag.  cpmdroid is step 2 of that plan; the code half is
done as of this round.

- W8 exports still cannot leave the sandbox by a path, and R8 imports still
cannot arrive by one - both are reduced to a leaf inside Imports/ and Exports/.
That is the right shape for Android and it is deliberate, but it is also the
open half of FEATURE_PARITY item 4(a) for both mobile ports: the parity target
is ACTION_CREATE_DOCUMENT for a real save-as on export, to sit beside the
Import File... picker that already covers arrival by staging.

- a zero-byte export is silently dropped.  emu_host_file_close_write() only
moves to WRITE_READY when the buffer is non-empty, so W8 on an empty CP/M file
tells the guest it succeeded and no file appears in Exports.  The CLI and
Windows backends both create the zero-byte file.  Small, and nobody has hit it,
but it is a divergence in the same contract this round was tightening.
