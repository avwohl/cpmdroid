NOTHING IN THIS TREE HAS BEEN THROUGH THE NDK SINCE 9b68ab1
------------------------------------------------------------

- [ANDROID] build c06fa58 before anything else.  It is the newest source commit
on master - emu_host_file_close_write() no longer requires a non-empty buffer to
reach HOST_FILE_WRITE_READY, nativeGetHostFileWriteData() gates on that state
rather than on the byte count, and handleHostFileWrite() treats an empty array
as a file to create - and it has never been compiled by the NDK, so a failure in
it is a failure at HEAD.  Both wrapper scripts are tracked now and pin Gradle
8.13; romwbw_emu and cpmemu must be checked out beside this repository, because
CMakeLists.txt compiles the core in place from ../romwbw_emu/src and
../cpmemu/src and stops with a FATAL_ERROR if they are missing; ndkVersion is
28.0.13004108 and assembleDebug needs no keystore.  Then run check 1 in
MANUAL_CHECKS.md.  Until both have happened, CHANGELOG.md's Verified section
must keep saying this fix was not built.

- [WINDOWS] gradle.properties pinned org.gradle.java.home to a Windows JDK path,
which Gradle rejects on every other host before it reads a build script, so the
line is commented out.  A Windows shell build now needs JAVA_HOME set instead;
Android Studio picks its own JDK and never read that property.  Confirm on the
next Windows build.

PARITY WITH THE OTHER PORTS
----------------------------

z80cpmw's FEATURE_PARITY.md describes this port from outside it, and README.md's
Related Projects section says which of these files back which rows.  After
changing them, run the reporter from here:
    sh ../z80cpmw/tools/check-sibling-drift.sh
It reads only, and exits non-zero when a column is behind the tree it describes.
Correcting a column is an edit in z80cpmw.

- [ANDROID] parity item 4(a) is open in both directions.  W8 exports cannot
leave the sandbox by a path and R8 imports cannot arrive by one; both are
reduced to a leaf inside Exports/ and Imports/.  There is no save-as
(ACTION_CREATE_DOCUMENT), no picker (ACTION_OPEN_DOCUMENT or GetContent), and no
share or view intent-filter in AndroidManifest.xml, so nothing can arrive from
another app either.  Files get in only by the user staging them into Imports/
with a file manager, which README.md tells them to do and which Android 11+
makes a fight - the stock Files app does not show Android/data at all.  The
leaf-only shape is deliberate for Android; the missing UI is not.
